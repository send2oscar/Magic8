# Local ComfyUI Bridge Architecture

## Purpose

`XXX` is a fixed Qwen apparel replacement feature. The website does not directly connect to ComfyUI, nor does it expose the user's computer's ComfyUI port. Instead, the Bridge on the user's computer actively fetches tasks from the website via HTTPS, calls the local-only ComfyUI, and returns the results to the website.

## Roles and Trust Boundaries

| Component | Responsibility | Visible Data |
|---|---|---|
| Dashboard | Logged-in users create `XXX` tasks, view secure progress and results | Own task status and results |
| Website Server | Verifies photo ownership, reserves/refunds credits, issues short-lived source URLs, saves output | Task metadata and controlled storage access |
| Local Bridge | Actively claims leased tasks, sends source images to `127.0.0.1:8188`, returns output | Source image and processing results for the current task |
| ComfyUI Desktop | Only executes local fixed Qwen workflows | Current work images uploaded by the Bridge |

## Task Data Flow

```text
User clicks XXX
    -> Website verifies photo and at least 10 credits, creates a durable task and reserves 10 credits
    -> Paired Bridge polls and claims task lease
    -> Website provides short-lived source URL + fixed Qwen workflow specification
    -> Bridge uploads image to localhost:8188, only replacing filename in LoadImage node 78
    -> Bridge submits workflow, polls local ComfyUI, reads output from node 102
    -> Bridge reports stages and uploads results
    -> Website saves results to controlled storage, completes history, and displays in Gallery
```

## Pairing and Credentials

The project owner generates a short-lived, one-time pairing code in the Dashboard. The Bridge exchanges this pairing code for a randomly generated device credential; the server only stores the credential hash. The browser does not obtain device credentials, and each API call simultaneously verifies device identity and task lease. Re-pairing revokes old devices.

This is not about setting up a public Bearer Token in front of ComfyUI. The Bridge's device credential is automatically generated by the pairing process and stored on the user's own computer, used to prevent others from impersonating a workstation to claim or return tasks.

## Task Status and Recovery Principles

Task statuses are `queued`, `leased`, `processing`, `completed`, or `failed` in sequence. The Bridge obtains a time-limited lease when claiming a task; if interrupted, the task can be safely re-leased or marked as failed after the lease expires. The server only refunds credits if the task has not yet terminated, to avoid duplicate refunds. If the Bridge is offline, the website will not deduct credits for new `XXX` tasks; tasks that have been created but timed out will be safely terminated and refunded upon subsequent queries or Bridge requests.

## Fixed Workflow Restrictions

The website will only provide the reviewed `qwen-image-edit-rapid` template. The Bridge is only allowed to inject the filename after ComfyUI upload into node `78` and only accepts image output from node `102`. The task will include the full prompt entered by the Dashboard user, and the Bridge must pass the prompt verbatim to the fixed workflow's prompt field; no adding, deleting, prefixing, or filtering of prompt content is allowed. No arbitrary workflow JSON, node IDs, or model names can be provided by the browser, task creator, or any source other than the Bridge.

## Network and Desktop Setup

ComfyUI should only listen on `127.0.0.1:8188`. DDNS, router port forwarding, CORS, external HTTPS reverse proxies, or public ComfyUI APIs are not required. The Bridge only needs to establish outbound HTTPS connections to the website; if the computer, ComfyUI, or Bridge is not running, `XXX` will show the workstation as offline and will not create billable tasks.

## Workstation Setup

To run the local Bridge, you need:

1.  **Node.js (LTS version)**: Download and install from [nodejs.org](https://nodejs.org/).
2.  **pnpm**: Install globally using `npm install -g pnpm`.
3.  **ComfyUI**: Ensure ComfyUI is installed and running on your local machine, listening on `127.0.0.1:8188`.
    -   It must have the `Qwen-Rapid-AIO-v11.4.safetensors` checkpoint and the `rgthree` custom nodes installed.

### Bridge Commands

Navigate to the `shirt-changer-app` directory on your workstation and use the following commands:

-   **Pairing**: Generates a device credential and stores it locally. This needs to be done once per workstation.
    ```bash
    pnpm bridge:pair -- --site https://your-site.example --code PAIRING-CODE [--label "My ComfyUI Workstation"] [--comfy-url http://127.0.0.1:8188]
    ```
    -   `--site`: The URL of your Shirt Changer application (e.g., `https://your-site.manus.computer`).
    -   `--code`: The one-time pairing code generated from the Shirt Changer Dashboard.
    -   `--label` (optional): A descriptive label for your workstation. Defaults to your computer's hostname.
    -   `--comfy-url` (optional): The URL where your local ComfyUI is running. Defaults to `http://127.0.0.1:8188`.

-   **Running the Bridge**: Starts the Bridge client, which will poll the Shirt Changer server for tasks and process them using your local ComfyUI.
    ```bash
    pnpm bridge:run
    ```

-   **Checking Bridge Status**: Verifies if the Bridge is paired and online.
    ```bash
    pnpm bridge:status
    ```

### Important Notes

-   The Bridge client stores its configuration (including the device credential) in a file located at `~/.shirt-changer-bridge/config.json` (or the path specified by `SHIRT_CHANGER_BRIDGE_HOME`). This file should be kept secure.
-   The Bridge only makes outbound HTTPS connections to the Shirt Changer website. It does not open any ports on your local machine to the internet.
-   If your ComfyUI is not running or is not accessible at the configured `--comfy-url`, the Bridge will report it as offline, and no `XXX` tasks will be created or charged.
